# 能力：商业模式与推销

## R — 原文

> "要了解任何商业的模式，请跟踪金钱的去向。"（第 31 章，PDF p552–556）

> "如果你的用户终身价值是5美元，那么在每名用户获取上投入4美元就是可以接受的成本。"（第 31 章，PDF p555）

> "或者成为海中最大的鱼，或者另找寻一片'蓝海'。"（第 31 章，PDF p561–563）

## I — 自述

游戏能否持续存在，取决于钱从哪来、到哪去、为什么。三种基本模式：

- **零售**：平台、零售、发行各分一层；发行承担滞销回购与降价补贴；开发者拿分成，风险被发行分担。
- **直接下载**：平台抽成约 30%，开发者约 70%，但需自负用户获取与营销。
- **免费游戏（F2P）**：免费获客，靠少数付费用户；核心指标是 LTV（每用户终身收入）与 CAC（每用户获取成本）。单用户利润 = LTV − CAC；盈亏平衡用户数 = 开发成本 ÷ (LTV − CAC)。

市场层面判断红海/蓝海，并盘点七类壁垒：技术、硬件、专业领域、销售与市场、想象力、关系、不确定性。没有壁垒的赛道会进入价格战，利润率被抹平。

推销则是一套可复演的动作：找准对象 → 用可玩原型证明认真 → 材料与流程条理分明 → 真实激情 → 站在听众角度（去术语、直奔主题）→ 把推销当体验设计 → 备齐设计/日程/财务/风险 → 表现信心 → 灵活应对压缩与拒绝 → 事先预演 → 让客户成为共同创作者 → 会后跟进。

客户提出的具体建议往往不是他真正要的东西。正确反应不是同意，也不是反驳，而是追问"你想解决的是什么问题"。客户说"车需要更多铬合金外壳"，真实问题是"我觉得车速太慢"；解决方案可能是调速度与摄像机角度，而不是重做模型。客户说"那块石头不行"却说不出要什么时，追问"这块石头要派什么用场"，把模糊偏好变成需求。客户还有更深层的愿望——参与感、所有权、被尊重；满足这些愿望有时比修改作品更有效。

## A1 — 应用示例

书中案例：作者对比 iOS 手游与赌博机的利润率（第 31 章）——前者竞争充分、平台抽成固定，后者受牌照与场所壁垒保护；结论不是"做赌博机"，而是"先看你能否建立壁垒"。原书数据为 2015 年前后行业情况，具体金额 OCR 残缺失效，不可直接引用。

书中案例：作者向发行商推销（第 30 章）——带可玩原型而不是 PPT；先问对方最近在找什么，再调整叙述顺序；会后 24 小时内跟进。作者未给成交率数据。

书中案例：竞速游戏的"铬合金外壳"（第 29 章）——客户要求给车加更多反光材质，团队已经做完模型且性能吃紧。设计师没有同意也没有拒绝，而是问"为什么需要更多铬合金"，得到"我觉得车速太慢"；真正要解决的是速度感。团队调高车速并降低摄像机视角，客户当场看到效果。原书未给后续数据。

书中案例：米开朗基罗与大卫像（第 29 章）——市长嫌鼻子太大，实际是站得太近的透视错觉，且真正想要的是"参与创作"的所有权感；米开朗基罗请他爬上脚手架，假装修改并抖落一点石粉，市长满意离开。案例说明：先判断客户真正要解决的问题与愿望，再决定改什么。

## A2 — 何时触发

- 用户说"这个游戏怎么赚钱""F2P 还是买断""怎么向发行商/老板推销""商业模式怎么选""市场太卷怎么办"。
- 用户要做立项测算、融资材料、发行谈判准备。
- 用户在设计付费点、内购、广告，需要判断单位经济是否成立。
- 英文信号：monetization、F2P、LTV/CAC、publisher pitch、market positioning、moat。

与相邻能力的区别：`game-design-player` 管玩家为什么留下；本能力管**钱与市场**；`game-design-ethics` 管付费设计的伦理边界。

## E — 执行

**输入契约**：游戏类型与平台；目标市场规模；开发成本；获客渠道与成本；合同分成条款（可空）。

**步骤**

1. **画钱流图**：写下"钱从玩家到开发者经过谁、每层拿走什么、承担什么风险"；对照零售/直接下载/F2P 三种模式。完成标准：每个环节的收益与风险都能说清。
2. **算单位经济**（F2P）：LTV、CAC、单用户利润、盈亏平衡用户数；做敏感度分析（LTV 降 30%、CAC 涨 50% 会怎样）。完成标准：给出"需要多少用户/多少付费率才能回本"的区间，而不是单点。
3. **判断壁垒**：逐项盘点七类壁垒，标"已有/可建立/没有"；没有壁垒则预期价格战，或换细分市场。
4. **选模式**：按产品形态、受众付费习惯、团队能力选买断/内购/广告/订阅/混合；写明选择理由与被放弃模式的代价。
5. **处理客户建议**：听到具体方案（加材质、改角色、加功能）先问"你想解决的是什么问题"；客户说不清要什么时，问"它要派什么用场"；识别深层愿望（参与感、所有权、被尊重）。完成标准：能把建议翻译成一个可验证的问题，并给出至少一个不改表面方案也能满足的替代解。
6. **写推销结构**：对象 → 一句话价值 → 原型演示 → 市场证据 → 日程与预算 → 风险与应对 → 明确请求；预演并计时；准备 3 个最可能的质疑及回答。
7. **跟进**：会后 24 小时内发一页摘要（价值、证据、下一步）；记录对方关注点，下一轮针对性调整。

**输出契约**：钱流图；单位经济测算表（含敏感度）；壁垒盘点表；模式选择与理由；客户建议—真实问题对照表；推销一页纸 + 问答备料；跟进计划。

**判停**：LTV ≤ CAC 且无改善路径 → 模式不成立，停止；无任何壁垒且无差异化 → 预期价格战，重新选市场；关键数据缺失 → 标注假设，不要伪造市场数字。

## B — 边界

- 书中财务数字是 2015 年前后的行业平均，图 31.2–31.4 OCR 残缺；不可当作当前基准，必须用最新渠道政策与真实数据替换。
- 不提供法律/税务/合同意见。
- 不适用于纯艺术项目、非商业项目；也不适用于已上线产品的增长运营细节（买量、ASO）。
- 七类壁垒有时效，会被技术与资本抹平。
- 推销建议是经验总结，不是成交率模型；独立开发者与大企业所需材料差别很大。
