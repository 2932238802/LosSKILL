# L0 常驻片段（AGENTS.md 顶部 12 行）

## 为什么是 12 行

`AGENTS.md` / `CLAUDE.md` 每次会话自动注入，是唯一不依赖触发词的层。
但它是**固定成本**：每多 10 行，每次会话都多付。所以只放三样：

1. 任务分级（决定动作）；
2. 交付前三问（决定能不能说"完成"）；
3. 一句指针（需要细节时再加载 L1）。

项目专属命令、雷区**不要**放这里，放 L2 `references/projects/<项目>.md`。

---

## 标准片段（原样复制）

```markdown
## 工程任务：按 leverage-protocol 执行

**先分级**：S 小改（单文件/无接口变更）→ 读相关文件 → 改 → 跑最近验证。
M 功能（跨文件/新接口）→ 先写 1 页方案与验收 → 实现 → 正常+边界验证。
L 重活（跨模块/数据/权限/发布）→ 先出 2–3 方案与回滚 → 确认 → 分步实现。
不确定按 M；涉及跨模块、数据迁移、权限/安全、发布，自动升 L。

**交付前必须回答**（答不出就标"未验证草稿"，不许说"应该可以"）：
1. 验证命令跑了吗？结果是什么？
2. 结论引用证据了吗？（文件:行 / 日志 / 测试名）
3. 改动涉及的文件读全了吗？没读的说明原因。

**协议全文与项目命令**：加载 `leverage-protocol` Skill；项目专属见其 `references/projects/`。
```

约 12 行、~180 tokens。

---

## 放置方式

### Claude Code

Claude Code 自动读 `CLAUDE.md`，不自动读 `AGENTS.md`。所以：

- `AGENTS.md`：放上面的标准片段（canonical）。
- `CLAUDE.md`：只放一行导入：

```markdown
@AGENTS.md
```

Claude Code 支持 `@path` 导入；这样两份文件不会各写一遍、逐渐漂移。

### Codex / Cursor 等

直接读 `AGENTS.md`，无需 `CLAUDE.md`。

### 已有 AGENTS.md / CLAUDE.md

- 片段放在文件**最顶部**（标题之后、其它内容之前），确保优先被读到。
- 已有 `CLAUDE.md` 且无导入：在顶部加 `@AGENTS.md`，不要复制正文。
- 两份都已存在且内容不同：以 `AGENTS.md` 为 canonical，人工合并一次，之后只改 AGENTS.md。

---

## 不要放进 L0 的东西

- 项目构建/测试命令（放 L2，且带最后验证日期）。
- 架构说明、目录树、长清单。
- 与"分级/三问/指针"无关的任何内容。
- 会频繁变化的版本号、端口、环境变量值。

---

## 验收 L0 是否生效

新开一个会话，问一个非平凡任务（如"帮我改一下 X"），观察：

- 回答是否先给出 S/M/L 判定或至少按分级行动；
- 交付时是否回答三问；
- 是否能说出"按 leverage-protocol"。

若没有，检查：
1. `CLAUDE.md` 是否有 `@AGENTS.md`；
2. 片段是否在文件顶部；
3. 宿主是否支持 `@` 导入（不支持就改为双写，见下）。

### 不支持导入时的降级

把标准片段原样复制进 `CLAUDE.md` 顶部；`AGENTS.md` 保留一份。两处内容必须一致，改动时同步。
