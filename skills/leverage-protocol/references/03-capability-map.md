# 能力地图：AI 能调什么、不能调什么

## 四层能力

### 1. 已装 Skill（可发现、可触发）

位置（按优先级）：

1. `~/.claude/skills/`
2. `<项目>/.claude/skills/`
3. `<项目>/skills/`（本仓库约定）

每个 Skill 是一个目录 + `SKILL.md`。**不要凭记忆**：跑

```bash
python3 scripts/capability_index.py query "<任务>"
```

索引会给出名称、路径、命中词。没有命中就明确说没有。

### 2. 内部能力卡（不可直接触发）

形如 `<skill>/references/capabilities/*.md` 的卡片，是某个入口 Skill 的内部资料。
它们**不是**独立 Skill，不会出现在宿主技能列表里；只能通过所属入口 Skill 使用。

判断：路径含 `references/capabilities/` → 内部卡，不是独立 Skill。

### 3. 潜在能力（模型已有知识，但可能不用）

12 个域：架构、设计模式、API 契约、数据模型、测试、安全、性能、并发、错误处理、
可观测性、文档/ADR、发布回滚。

这些不需要安装，但需要被"想起来"。用 `02-triggers.md` 与 `domains.json` 匹配。
原则：只在会改变做法时提，最多 3 项。

### 4. 宿主工具与权限

| 能力 | 边界 |
|---|---|
| 读文件 | 可读工作区；越界或敏感文件先问 |
| 写文件 | 可写工作区；删除/覆盖前先看目标 |
| Shell | 非破坏性命令可直接跑；删除、重置、发布、外传先确认 |
| 网络 | 视宿主配置；不可用时说明 |
| 子代理 | 可用则并行；不可用则串行并说明 |

不确定是否有权限时：**先问，不擅自越权**。

## 盲区清单（必须承认）

- 看不到未安装的 Skill；看不到其他机器的技能库。
- 看不到运行时状态（服务是否在跑、数据库内容、线上日志），除非用户提供或授权读取。
- 不知道用户的完整上下文、团队约定、历史决策。
- 文档与命令可能过期；L2 项目文件必须带"最后验证日期"。
- 模型知识有截止时间；涉及版本/API 变更时要查证。
- 不知道用户"没说出来"的目标；必要时先问一句。

**处理原则**：不知道就说不知道，然后查；查不到就标注假设。

## 路由决策

```text
任务进来
  ├─ query 命中已装 Skill？
  │    ├─ 是 → 读该 SKILL.md，按它执行；必要时补读 1 个相邻 Skill
  │    └─ 否 → 继续
  ├─ 潜在能力域匹配？
  │    ├─ 是 → 取 1–2 个检查点；改变范围先问
  │    └─ 否 → 继续
  └─ 通用方法执行，明确说明"没有套用现成技能"
```

---

## 不该做的事

- 把内部能力卡说成"独立 Skill"。
- 为了显得能力强，声称有某个没装的 Skill。
- 一次加载 3 个以上 Skill；上下文会互相稀释。
- 把"潜在能力"当成必须执行的清单；它只是提醒。
- 修改用户设置、安装/卸载 Skill、改 `CLAUDE.md`/`AGENTS.md`，除非用户明确要求。
