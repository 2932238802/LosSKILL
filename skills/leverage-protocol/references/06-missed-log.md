# 漏用复盘（Missed Log）

## 为什么要有

触发器表不会自己变好。只有把"本该用却没用的能力"记下来、回收进触发器，下一次才会真的想起来。

但**只写不读的日志不如没有**。所以本文件同时定义回收机制与删除条件。

---

## 什么时候记

满足任一条：

- 交付后你意识到"其实应该先做架构/测试/安全检查"。
- 用户说"你怎么没提醒我 / 这个不是应该考虑吗"。
- 同类问题第二次出现。
- 一次返工本可避免。

不记：琐碎风格问题、用户明确拒绝过的能力、与能力域无关的失误。

---

## 条目模板

```markdown
### YYYY-MM-DD · <任务类型>

- 任务：<一句话>
- 漏掉的域：<架构/测试/安全/并发/...>
- 为什么漏：
  - [ ] 触发信号没写进表
  - [ ] 信号有，但被忽略
  - [ ] 信号有，但优先级判断错
  - [ ] 用户明确拒绝（不记，除非反复出现）
- 应该怎么做：<一句话动作>
- 回收动作：
  - [ ] 在 `02-triggers.md` 加信号
  - [ ] 在 `domains.json` 加关键词
  - [ ] 在项目 L2 加雷区
  - [ ] 无需改动（一次性）
```

---

## 回收机制

- **每 2 周或满 5 条**，做一次 15 分钟复盘：
  1. 按"为什么漏"分类；
  2. 重复出现的信号 → 写进 `02-triggers.md` / `domains.json`；
  3. 项目特有的 → 写进 `references/projects/<项目>.md`；
  4. 一次性问题 → 标"无需改动"。
- 回收后保留条目，但在标题加 `[已回收]`。
- 3 个月内未再出现的信号，可以从触发器表移除（避免表膨胀）。

---

## 删除条件

出现以下任一情况，删除本文件对应的日志内容（保留模板）：

- 连续 3 个月没有新条目；
- 团队没有任何人读；
- 回收动作从未发生。

**日志的价值在回收，不在记录。** 不回收就删掉，别制造"我们在改进"的错觉。

---

## 示例

```markdown
### 2026-11-19 · 功能开发（Theseus 站内信）

- 任务：给站内信加"全部已读"按钮
- 漏掉的域：并发 / 数据一致性
- 为什么漏：
  - [x] 触发信号没写进表（"全部已读"没有对应信号）
  - [ ] 信号有，但被忽略
- 应该怎么做：批量更新要考虑并发点击与部分失败，先确认幂等与事务边界。
- 回收动作：
  - [x] 在 `02-triggers.md` 的"数据/批量更新"行加"全部已读/批量操作"
  - [x] 在 `domains.json` 的 concurrency 加"批量"
```
