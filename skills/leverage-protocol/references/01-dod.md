# 完成定义（DoD）：证据长什么样

## 原则

**没有证据的"完成"只是意见。** 本文件定义什么算证据、什么不算，以及不同任务类型的最低交付。

---

## 一、算证据的

| 类型 | 形式 | 例子 |
|---|---|---|
| 代码位置 | `文件:行` | `backend-rust/src/routes/auth.rs:142` |
| 命令结果 | 命令 + 关键输出 | `cargo test --all-targets` → `test result: ok. 148 passed; 0 failed` |
| 测试 | 测试名 + 结果 | `test_login_rejects_expired_token ... ok` |
| 复现 | 步骤 + 前后现象 | "改前 3/10 次失败；改后 50/50 通过" |
| 日志 | 带上下文的片段 | `ERROR ... request_id=... status=500` |
| 静态检查 | 工具 + 结论 | `cargo clippy --all-targets -- -D warnings` → exit 0 |
| 外部事实 | 可点开的来源 | RFC/文档链接 + 引文 |

## 二、不算证据的

- "我检查过了" / "应该没问题" / "理论上可以" / "看起来正确"
- "已经修复" 但没有改动位置或验证
- 只贴代码，不说明是否编译/测试
- 跑了一个无关命令，冒充验证
- 把"没有报错"当作"行为正确"（可能根本没覆盖到）

---

## 三、按任务类型的最低交付

### 改代码（S）

- [ ] 读了将改的文件与直接调用方
- [ ] 改动有 `文件:行`
- [ ] 跑了最接近的验证（编译/格式化/相关单测）
- [ ] 未跑的验证写明原因

### 新功能（M）

- [ ] 1 页方案：输入/输出/失败语义/验收标准
- [ ] 实现位置
- [ ] 正常 + 边界 + 失败路径测试（或说明为何不能）
- [ ] 兼容性/迁移影响

### 跨模块/数据/权限（L）

- [ ] 2–3 个方案与取舍（成本/风险/可逆性）
- [ ] 推荐方案与理由
- [ ] 回滚路径
- [ ] 分步验证记录
- [ ] 用户确认记录（若需要）

### 排查故障

- [ ] 复现步骤或证据（日志/指标/最小样例）
- [ ] 根因假设按可能性排序
- [ ] 最小修复
- [ ] 回归验证（修前失败、修后通过）

### 架构/方案

- [ ] 现状与约束
- [ ] 2–3 个候选
- [ ] 取舍矩阵（成本/风险/可逆性/团队熟悉度）
- [ ] 推荐与"什么情况下改推荐"

### 写文档

- [ ] 读者是谁
- [ ] 能照做的步骤/命令
- [ ] 与代码一致性检查（版本/路径/名称）
- [ ] 已知限制

### 数据分析

- [ ] 口径、来源、时间范围
- [ ] 计算过程
- [ ] 交叉核对（第二种算法/抽样）
- [ ] 不确定性说明

---

## 四、允许 `N/A`，但必须带理由

示例：

- "回滚：N/A（纯本地脚本，无部署）"
- "边界测试：N/A（改动仅调整日志文案，无行为分支）"
- "弱序验证：未做（无 ARM64 硬件）；已做 Miri + loom 静态检查"

`N/A` 不是免死金牌；理由必须成立，且不能用来掩盖"懒得做"。

---

## 五、完成声明模板

```text
已完成：<一句话>
证据：
- <文件:行 / 命令输出 / 测试名>
未做/未验证：
- <项>：<原因>；<用户可执行的命令>
```

不超过 6 行。细节放正文，不堆在结尾。
