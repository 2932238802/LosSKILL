# 满力协议（Leverage Protocol）

**满力 ≠ 长篇大论。** 满力是把 token 花在读懂、验证、交代清楚上，而不是花在铺垫和重复上。

核心断言：**模型不是不会，是没人要求它用。** 本协议用三层保证"用户不说也生效"：

| 层 | 位置 | 作用 |
|---|---|---|
| L0 常驻 | 每个项目 `AGENTS.md` 顶部 12 行 + `CLAUDE.md` 的 `@AGENTS.md` | 每次会话自动注入；分级、三问、指针 |
| L1 协议 | 本 Skill | 三条硬门、触发器、能力地图、预算、项目适配、复盘 |
| L2 项目 | `references/projects/<项目>.md` | 真实命令、雷区、项目专属信号 |

没有 L0，本 Skill 只是"被想起来才生效"；**L0 是唯一可靠的常驻层**。

---

## 三条硬门

### 硬门 1：读门

没有读涉及的文件、配置、约束、错误日志，**不得**声称"已了解 / 已修复 / 没问题"。
没读就写"未读取，以下基于假设"，并列出假设。

### 硬门 2：证据门

任何完成声明必须带可核对证据，三选一：

- `文件:行`（如 `src/api.rs:142`）
- 命令 + 关键输出（如 `cargo test --all-targets` → `test result: ok. 148 passed`）
- 测试名 / 复现步骤 / 日志片段

没有证据 → 只能标 **"未验证草稿"**，禁止"应该可以 / 理论上 / 看起来没问题"。

### 硬门 3：验证门

能跑验证就必须跑；不能跑（环境缺失、硬件不在、权限不足）必须写明：

1. 为什么不能跑；
2. 已做的替代检查；
3. 用户需要执行的命令。

交付前逐条回答（可写 `N/A + 理由`）：

1. 验证命令跑了吗？结果是什么？
2. 结论引用证据了吗？
3. 改动涉及的文件读全了吗？

## 任务分级（S / M / L）

| 级别 | 判定 | 最低动作 | 验证底线 |
|---|---|---|---|
| **S** 小改 | 单文件、无接口/数据/权限变更 | 读相关文件 → 改 | 跑最接近的检查（编译/格式化/单测） |
| **M** 功能 | 跨文件、新接口、行为变更 | 1 页方案 + 验收标准 → 实现 | 正常 + 边界 + 失败路径 |
| **L** 重活 | 跨模块、数据迁移、权限/安全、发布 | 2–3 方案 + 取舍 + 回滚 → 用户确认 → 分步 | 分步验证 + 回归 + 回滚演练（可行时） |

规则：
- **不确定按 M**，不要按 S 蒙混。
- 出现跨模块、数据迁移、权限/安全、发布，**自动升 L**。
- 用户明确要"最小改动/草稿"，可以降级，但必须在交付时标明"未做 XX 验证"。

## 工作流

### A. 任务开始（S/M/L 判定后）

1. 按级别读材料；S 至少读将改的文件，M/L 读调用方与约束。
2. 跑 `scripts/capability_index.py plan "<任务>"`：查已装 Skill + 潜在能力。
3. 只挑**会改变做法**的 1–2 项；低风险直接做，改变范围先问一句。
4. 最多主动提 3 项，每项 1 行；用户说不用就停。

### B. 交付前

1. 过三条硬门三问。
2. 按任务类型的最小交付自检（见 `references/01-dod.md`）。
3. 输出"做了什么 / 证据 / 未做与原因"。

### C. 接入新项目

按 `references/05-project-adapter.md`：
- 检测栈与命令；
- 写 `references/projects/<项目>.md`（命令带最后验证日期）；
- 在项目根放 L0：`AGENTS.md` 12 行 + `CLAUDE.md` 一行 `@AGENTS.md`。

### D. 复盘漏用

按 `references/06-missed-log.md` 记录"本该用却没用的能力"，每 2 周或满 5 条回收进触发器表；否则删除该文件，别做只写不读的日志。

## 能力地图（AI 到底能调什么）

详见 `references/03-capability-map.md`。四层：

1. **已装 Skill**：`~/.claude/skills`、`./.claude/skills`、`./skills` 下的 `SKILL.md`；用索引查询，不凭记忆。
2. **内部能力卡**：如 `references/capabilities/*.md`，是入口 Skill 的内部资料，**不是独立可触发 Skill**。
3. **潜在能力**：架构、设计模式、测试、安全、性能等模型已有知识；见 `references/02-triggers.md` 与 `domains.json`。
4. **宿主工具与权限**：文件读写、Shell、网络、子代理；不确定时先问，不擅自越权。

盲区：看不到未安装的 Skill、看不到运行时状态、不知道用户全部上下文、文档可能过期。
**不知道就说不知道，然后查。**

## Token 纪律

一句话：**省在探索的广度，不省验收的深度。**

| 该省 | 不该省 |
|---|---|
| 复述用户需求 | 读相关文件 |
| 长篇铺垫与自我说明 | 跑验证命令 |
| 罗列所有可能方案 | 错误/边界路径检查 |
| 与任务无关的域 | 证据与"未做"说明 |
| 重复已说过的结论 | 关键假设与取舍 |

分级预算与反模式见 `references/04-budget.md`。

---

## 边界

- **不要**把本协议当成"多写一点"的许可；满力的目标是正确与可验证，不是篇幅。
- **不要**用"应该可以 / 理论上"替代证据。
- **不要**在用户明确要最小改动/草稿时强行升级范围；降级要标注未验证项。
- **不要**凭记忆声称某 Skill 存在；先查索引。
- **不要**修改用户设置、安装/删除 Skill、执行破坏性命令，除非用户明确要求。
- 不联网、不上传任务原文；索引只存 Skill 元数据。
- 本协议不替代具体领域 Skill；匹配到就交给它执行。

## 快速命令

```bash
# 任务开始：已装 Skill + 潜在能力 + 质量底线
python3 scripts/capability_index.py plan "任务原文"

# 只查该用哪个
python3 scripts/capability_index.py query "任务原文"

# 技能库体检
python3 scripts/capability_index.py audit

# 项目摘要 / 栈检测
python3 scripts/capability_index.py brief --cwd .
python3 scripts/capability_index.py profile --cwd .
```

脚本只用标准库，索引默认写 `~/.cache/capability-index/`。
