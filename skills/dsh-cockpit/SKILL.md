# 派单驾驶舱：把活交出去、看得见、收得回

## 触发与不触发

**适用**

- 「把这件事交给 Claude Code」「让它改完再自查」
- 「它为什么卡住了」「它刚才跑了什么」「要我批什么」
- 「把这任务拆一下」「推到任务表 / 在线文档里去」
- 「今天花了多少」

**不适用**

- 只是写个文案、查个资料、改一行配置——自己做，别派（单次底线约 $0.05）
- WorkBuddy 客户端的按钮怎么点（那是产品操作，不是这条流水线）

## 输入检查（缺什么先问，别猜）

派单前必须有**四件套**，缺一件就先补：

1. **现象**：现在是什么样（可观察的，不写「有点乱」）
2. **照哪做**：哪份文档的哪一节 / 哪个文件（给指针，不要贴全文）
3. **怎么验**：跑什么命令、看到什么算通过
4. **回一句**：要回执，回执写「结论 + 证据 + 改了哪些文件」

可选：归属（Claude Code / WorkBuddy）、是否续接上一条会话。

## 核心原则（常驻）

1. **一次派单 = 一件完整活**。每次调用有固定开销（约 12–13K 输入 token），来回追问最贵。
2. **能自己做就别派**。派给它是为了「它能在仓库里动手、有自己的一套工具」，不是为了省钱。
3. **轮次才是成本**。同一件活 4 轮比 2 轮贵约 40%，一半花在「命令被拒 → 重试」。给对权限通配符（`Bash(cmd:*)`）比事后批准便宜。
4. **没有证据的回执等于没回执**。只说「好了」不算完成。
5. **被拒就是没干成**。`denied` / `error` / `timeout` 都不算完成，要进授权队列或打回。
6. **续接省 token 和延迟，不省钱**。目标网关对缓存读也收费，别把「省钱」当续接的理由。

## 执行步骤

1. **判断该不该派**
   - 需要它在仓库里改多处、跑验证、读文档 → 派
   - 一句话能说清且自己能做 → 自己做

2. **派活**（开发）
   - 用四件套写任务；给 `Bash(命令:*)` 前缀通配，不要写精确命令（模型会把命令包成 `cmd 2>&1; echo $?`，精确匹配会失效）
   - 允许改文件时必须显式放行写权限，否则它只能读

3. **收回执**
   - 看：状态、轮次、时长、花费、被拒列表、以及回执正文里的命令与退出码
   - 状态非 ok → 看被拒的命令，决定「补权限重试」还是「打回重写」

4. **处理授权**
   - 被拒的命令进授权队列，等人批准；批准后规则记账（以后同类活不再问）并按原任务重派一次
   - 不是所有拒绝都能靠放行解决：有些是执行侧自身的静态分析规则（例如内联代码无法分析），这种要改写法（写成脚本文件再跑），批准也没用

5. **复核**
   - 用**新会话**做独立复核，但必须同时给它：需求文档路径、`git diff --stat`、原始验收判据
   - 只给「你看看有没有问题」= 假复核

6. **验收与收尾**
   - 自动化检查全绿 + 人工走查关键路径（两者缺一都不算完）
   - 记：改了什么、证据、参与方、下一步；花费进台账

## 输出模板

```markdown
## 回执
结论：<一句话，说清做成了什么 / 卡在哪>
证据：
- 命令：<命令> → 退出码 <n>
- 检查：<一共几条通过 / 差异集合>
- 改动：<文件清单，或文档的哪一节>
花费：<轮次> 轮 / <金额> USD
下一步：<谁做什么；或「无，结案」>
```

任务池条目（拆分子任务时）：

```
cc: <给 Claude Code 的子任务，一句话一个动作>
wb: <给 WorkBuddy 的子任务，写清要落到哪份文档的哪一节>
```

## 常见错误

- ❌ 把整篇文档 / 整份 diff 贴进任务正文 → ✅ 给路径，让它自己读
- ❌ 写精确的 `Bash(npm run typecheck)` → ✅ 写 `Bash(npm run typecheck:*)`
- ❌ 回执写「已修复」 → ✅ 写命令、退出码、差异集合
- ❌ 复核用同一条会话 → ✅ 新会话 + 判据 + diff
- ❌ 把「没回执」当成「还在做」 → ✅ 进未回执清单，主动催或重派
- ❌ 小事也派 → ✅ 自己三分钟能做完的自己做

## 边界与判停

必须先停、先问人：

- 涉及删数据、改生产、`git reset --hard`、`git clean`、动 `.env` / `data/`
- 一次改动跨模块或超过 5 个文件
- 花费超过当日预算的一半
- 被拒命令补了权限仍然过不去（说明是另一层规则，要换方案而不是硬试）
- 需要人拍板的取舍（两条路都合理时，给方案让人选，不要自己选）

**不要**：为了让流程走通而放宽 `bypassPermissions`、跳过验证、或用低质量兜底冒充成功。
