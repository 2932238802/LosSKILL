## 缺陷清单（按严重度降序）

### [P2] R-006 的 usage 去硬编码只覆盖 5/8 个脚本，3 个 install-* 仍依赖固定行号

- 位置：`scripts/install-claude-config.sh:22`（`sed -n '2,11p'`）、`scripts/install-git-hooks.sh:24`（`sed -n '2,7p'`）、`scripts/install-vscode-config.sh:31`（`sed -n '2,12p'`）
- 问题：`00-requirements-intake.md:51` 明确「8 个脚本的 usage() 使用硬编码行号」，成功指标为「所有脚本 -h 输出完整，不依赖固定行号」；设计 §6.4 要求「禁止固定行号；所有脚本统一一种方式」。本次只改了 5 个（worklog / finish-report / bootstrap-project / new-skill / sync-skills），上述 3 个 install-* 仍原样保留。
- 触发条件：脚本头部注释块增长到超出固定上界（本 Agent 用插入 5 行演示；claude/vscode 插入 2 行以上、git-hooks 插入 3 行以上即可越界）。
- 影响：`-h` 静默截断帮助，新增选项后用户看不到；与 R-006 要消除的缺陷同类，且违反「所有脚本统一一种方式」。不影响 `finish-report` / `worklog` 运行逻辑。
- 证据：`git grep -n "sed -n '2," HEAD -- scripts` 共 8 个脚本；工作区复查仍有 3 个；5 行插入后 `install-git-hooks` 的 `-h` 只剩标题与插入行，`用法`/所有选项全丢；claude/vscode 丢失最后选项。
- 建议：对 3 个脚本套用同一 awk `usage()`（或抽公共函数，需评估是否属新文件/新依赖）；T-006 selftest 增加「头部插入 N 行后所有脚本 `-h` 仍含最后选项」用例。
- 置信度：高

### [P2] `setup.sh -h` 使用固定行号且把代码行作为帮助输出

- 位置：`setup.sh:59`（`sed -n '2,12p'`），头部注释止于第 8 行，第 10–11 行为代码。
- 问题：`./setup.sh -h` 输出末尾包含 `set -uo pipefail` 与 `cd "$(dirname "$0")"`，帮助文本混入代码；同样是固定行号实现。
- 触发条件：任意一次 `./setup.sh -h`（必现）。
- 影响：帮助信息错误/误导；与 R-006 的「输出完整、不依赖固定行号」目标同类。`setup.sh` 不在 intake 的「8 个脚本」（指 `scripts/` 下）计数内，故不升 P1，但设计 §6.4「所有脚本」覆盖它。
- 证据：`bash setup.sh -h | tail -3` → `...`、`set -uo pipefail`、`cd "$(dirname "$0")"`。
- 建议：与 P2-1 同批用 awk 截取，或在 R-006 中明确排除 `setup.sh` 并登记为后续项。
- 置信度：高

### [P3] `--force` 重跑 AUTH 会追加新 AUTH 块但沿用同一幂等键

- 位置：`scripts/finish-report.sh:236-283`
- 问题：`--force` 时即使幂等键已存在也生成新 AUTH ID，导致同一幂等键对应多条 AUTH；新版帮助文案「忽略已存在记录，重跑回填与 AUTH；WORKLOG 仍按全键去重」与实际行为一致（WORKLOG 确实不重复），但「忽略已存在记录」易被读成不重复。
- 影响：台账可能出现同键多条 AUTH（需人工清理）；属 T-004 既有行为，T-005 仅改文案，未扩大范围。
- 建议：在 T-006 或后续 CR 决定 `--force` 是否应替换而非追加 AUTH；当前文案可再明确「AUTH 会新增一条」。
- 置信度：高
